# Lessons

Every failure, newest first: what happened, why, what it cost, and the rule or check that prevents a repeat. Skim before similar work.

| Date | What happened | Root cause | Cost | Prevention |
| --- | --- | --- | --- | --- |
| 2026-11-04 | App installed and "Launch ok", but it closed at once when opened on the iPhone | `-lhudnav_ffi` with the iOS release folder in the search path: ld picks `libhudnav_ffi.dylib` (the cdylib kept for UniFFI library mode) over the `.a` in the same folder, so the app needed a dylib from a Mac path; `devicectl launch` reports ok before the crash | One build round trip with the user | Static archive linked by full path in `project.yml`; `ios-build.sh` fails if `otool -L` shows the app linking `libhudnav_ffi`; "Launch ok" only means the launch was requested |
| 2026-11-03 | First Mac build stopped at signing: Xcode's Apple ID login rejected, so no provisioning profile | Xcode's saved account session for the Personal Team had expired; the script showed only the raw log tail | One round trip with the user; Swift not compiled yet | `ios-build.sh` prints the failing command's distinct `error:` lines and the fix for a rejected login; Xcode sign-in is checked before a build session |
| 2026-11-03 | Plan said Claude runs `scripts/ios-build.sh` in Terminal through computer use | Computer use grants terminals the "click" tier: no typing, no key presses, no paste | Plan corrected before any attempt; the build is a user step | The user types build commands; Claude gives them as one line to paste and reads the stage lines back |
| 2026-11-03 | Two scripted edits went wrong: one to `ffi/src/lib.rs` silently did nothing (compiler caught it), one spliced `docs/STATE.md` at stale offsets (seen in the output) | Replacement targeted text from before `cargo fmt`; offsets computed before an earlier replacement in the same script | Two redo rounds | Scripted edits assert the old text is present, compute offsets after every other change, and the result is read back; or use the Edit tool |
| 2026-11-03 | Clippy `dead_code` on two run stages' fields | Fields kept "for later" in a state machine | Caught by `core-check.sh` before push | Keep only what a later stage reads |
| 2026-11-03 | `cargo fmt --check` failed in `core-check.sh` | An edit made after the last `cargo fmt` | Caught locally before push | Run `scripts/core-check.sh` as the last step after all edits (rule 4) |
| 2026-11-03 | Constants script: one unreadable entry in `_FINGERPRINT_KEYS` hid the whole table | Dict evaluation was all-or-nothing, so a new brand upstream would have broken the build with Hyundai intact | Caught by a test before push | Skip unreadable entries, require the one needed; same case tested in the core parser |
| 2026-11-03 | A watcher reported the push "still running" after it had finished | `pgrep -f "git push"` matched the watcher's own command line | One false alarm | Wait on a process by PID or on its exit, never by `pgrep -f` on a string the watcher itself contains |
| 2026-11-03 | Rewrite of the project brief refused | The Projects tool only rewrites a doc whose current text was read in this conversation | One round trip | `project_read` a project doc before `project_write` |
| 2026-11-03 | crates.io blocked in the morning, reachable in the evening session | Workspace network allowlist differs between sessions | A zero-dependency design driven by a temporary limit | Check registry access at session start; core deps vendored so either state works (`scripts/core-check.sh`) |
| 2026-11-03 | openrouteservice `/plans/` looked up from Claude's side, but the user saw a 404 | A fetch result can come from a cache; it does not prove a page is live | One wrong answer, one round trip | Check a page's live state in the browser pane before telling the user it works |
| 2026-11-03 | Click on "Create repository" (public) refused by a safety check | Creating public content needs the user's own click | One round trip | Plan public creations (repos, posts) as a user click, with the form pre-filled |
| 2026-11-03 | CI bindings step failed: `libhudnav_ffi.so` not found | `ffi` built only `staticlib` + `lib`; UniFFI library mode reads a `cdylib`. The step could not run locally (crates.io blocked) | One CI round trip, ~3 min | CLAUDE.md rules 4 and 5; same command in CI and `scripts/ios-build.sh` |
| 2026-11-03 | Diagnostic test failed: reason sanitizer kept 16 chars of a whole message | Sanitizer filtered characters instead of keeping only the leading code; part of a token could leak | Caught by the test before push | Sanitizers keep the minimum by default (leading code only) |
| 2026-11-03 | crates.io unreachable from Claude's cloud workspace | Network allowlist of the workspace | Restructure into a dependency-free core + separate `ffi` crate | Check registry access at session start; see newer row for the vendored setup |
